# Chun Memory

> 一个基于 Markdown 文件的「会话记忆 / 上下文管理」工具。

当你说出「记录」时(类似的语句也行)，它会将当前对话的完整原文，以及生成的图片、代码、HTML 等内容存档到 `D:\Mark`。

以后只需说「回忆……」，它就能从档案中精准找回之前的对话和产出，并告诉你内容出处。

---

## ✨ 它解决什么问题

随着 AI 对话越来越长、跨越的会话越来越多，前面的内容很容易被遗忘或混淆。

Chun Memory 使用一套 `.md` 文件建立长期记忆，让之后的对话——无论是同一个 AI，还是另一个 AI——都能重新找到：

- 之前讨论过什么
- 做过哪些决定
- 生成过哪些内容
- 相关文件存放在哪里

---

## 🚀 使用方法

### 方式一：手动触发

| 触发词 | 功能 |
| --- | --- |
| `记录` / `存档` / `记住` | 将当前对话分段写入 `D:\Mark`，归档生成物并更新索引 |
| `回忆……` | 根据索引定位原始文件，精准回答并标明出处 |

> 触发词不必完全一致，意思相近即可。

### 方式二：自动记录

当对话内容接近 **150k tokens** 时，自动执行一次记录。

## 📁 文件存在哪里

默认存放位置：

```text
D:\Mark\
├── index.md
│   └── 总索引：用于查找不同的会话文件夹
│
└── 2026-09-06-1830-记忆skill设计\
    ├── index.md
    │   └── 本次会话的索引
    │
    ├── 001.md
    │   └── 第 1 段对话原文（约 ≤150k tokens）
    │
    ├── 001-assets\
    │   └── 第 1 段中的图片、代码、HTML 等生成物
    │
    ├── 002.md
    │   └── 第 2 段新增内容，不重复记录
    │
    └── ...
```

使用前可能需要手动创建 `D:\Mark` 文件夹。

## 🧠 核心设计

### 1. 全量原文 + 分段存储

要实现精准回忆，就必须保留完整原文。

但单个文件过长会影响读取，因此按照约 **150k tokens** 划分为一段，并在每段开头记录摘要和关键词。

### 2. 非重叠增量记录

每个分段只保存新增内容，不重复写入已经归档的对话，从而减少空间占用。

### 3. 分块写入

较长内容会拆分成多批写入，降低中途截断和内容丢失的风险。

### 4. 两级索引

采用以下检索结构：

```text
总索引 → 会话索引 → 分段原文
```

它类似于：

```text
目录 → 章节 → 正文
```

查找内容时先读取索引，再定位到对应的原文。

### 5. 生成物归档

图片无法直接保存在 Markdown 原文中，因此会被复制到对应的 `-assets` 文件夹。

Markdown 文件则负责记录文件路径和相关说明。

### 6. 任何 AI 都能使用

它不依赖特定平台的内置记忆能力，而是使用：

- 普通 Markdown 文件
- 清晰的目录结构
- 两级索引
- 索引头部的使用说明

只要 AI 能够读取这些文件，就能按照索引找回历史对话和生成内容。
